1. Problem Statement


The current model achieves 1.00 overall accuracy — which sounds excellent but is entirely misleading. With 52,437 non-stressed samples against only 223 stressed samples, a classifier that predicts "no stress" on every single input would score 99.6% accuracy. The model has learned exactly this shortcut.

WHY THIS IS DANGEROUS  Missing a stressed user is a false negative — the worst failure mode for a wellbeing detection product. The model currently misses 13 out of 45 stressed test samples. Every missed detection is a user who needed support but received none.

3. Data Balancing Techniques


The following techniques address the 235:1 imbalance. The recommended approach is to combine SMOTE with cost-sensitive weighting rather than relying on either alone.

Technique	How it works	Setting	Trade-off	Verdict
SMOTE	Generates synthetic minority samples via interpolation	sampling_strategy=0.1 (1:10 target ratio)	Good recall lift; risk of noisy samples at extreme ratio	Recommended
Class weights	Penalises misclassifying minority class during training	scale_pos_weight=235 in XGBoost	Zero data generated; fast; may underfit minority	Use alongside SMOTE
ADASYN	Adaptive SMOTE — generates more samples near decision boundary	sampling_strategy=0.1	Better boundary coverage; computationally heavier	Try if SMOTE plateaus
Undersampling	Removes majority class samples randomly	RandomUnderSampler(ratio=0.1)	Loses data; not recommended at 235:1 with only 223 minority	Avoid
Threshold tuning	Lowers prediction threshold from 0.5 to optimum	Sweep 0.05–0.40 on predict_proba	Free performance gain; no retraining needed	Always do this

3.1  Recommended combination
Use SMOTE to bring the ratio from 235:1 down to 10:1, then set scale_pos_weight=10 to handle the residual imbalance. This avoids generating too many noisy synthetic samples while still giving the model a strong signal to learn minority patterns.

from imblearn.pipeline import Pipeline
from imblearn.over_sampling import SMOTE
from xgboost import XGBClassifier

pipe = Pipeline([
    ('smote', SMOTE(sampling_strategy=0.1, random_state=42)),
    ('model', XGBClassifier(
        scale_pos_weight=10,
        n_estimators=400,
        max_depth=8,
        learning_rate=0.1,
        subsample=0.9,
        colsample_bytree=0.9,
        eval_metric='logloss',
        random_state=42
    ))
])

CRITICAL  Always wrap SMOTE inside imblearn.pipeline.Pipeline when doing cross-validation. If you apply SMOTE to the full training set before CV, synthetic test-fold points leak into training and CV scores become falsely optimistic by a wide margin.

4. Feature Engineering v2


The current 5 features capture basic typing speed and hold patterns. The following additional features are specifically high-signal for cognitive load and stress detection from keystroke dynamics research.

Feature	Formula	Why it helps
IKI entropy	scipy.stats.entropy(np.histogram(pauses)[0])	Stressed typists have more irregular inter-key intervals — entropy captures this unpredictability
Hold-time CV	std(holds) / mean(holds)	Normalises hold variance for typing speed; pure variance misleads fast vs slow typists
Digraph latency	mean(t_release_key1 → t_press_key2) for common bigrams	Transition time between specific key pairs degrades under cognitive load
Error burst rate	runs of >=2 consecutive backspaces / total keys	Stress causes clusters of corrections, not isolated typos
Session KPM z-score	(window_kpm - user_mean_kpm) / user_std_kpm	Relative speed drop is more meaningful than absolute KPM

5. Evaluation Strategy


5.1  Metrics to report (mandatory)
•Minority class F1  — primary metric
•PR-AUC (precision-recall area under curve)  — best single number for imbalanced tasks
•Minority precision and recall (separately)
•Confusion matrix on held-out test set
•Macro F1  — secondary overview metric
•Optimal classification threshold (from PR curve)

5.2  Metrics to STOP using
REMOVE FROM REPORTS  Overall accuracy must be removed as a primary metric. It is meaningless at 235:1 imbalance and actively misleads evaluation. Any stakeholder report showing accuracy >= 99% for this task should be treated as incorrect.

5.3  Threshold tuning
The default 0.5 prediction threshold is calibrated for balanced datasets. At 235:1 imbalance it suppresses almost all class 1 predictions. After training, sweep thresholds and pick the one maximising minority F1:

probs = model.predict_proba(X_test)[:, 1]
best_t, best_f1 = 0.5, 0
for t in np.arange(0.05, 0.50, 0.01):
    f1 = f1_score(y_test, probs >= t)
    if f1 > best_f1:
        best_t, best_f1 = t, f1
print(f'Optimal threshold: {best_t:.2f}, F1: {best_f1:.3f}')

7. Risks & Mitigations


Risk	Level	Impact	Mitigation
SMOTE data leakage	High	Synthetic points from test fold contaminate training, inflating CV scores.	Always use imblearn.pipeline.Pipeline. Never fit SMOTE on full dataset before splitting.
Over-sampling ratio	Medium	Going to 1:1 with 235x SMOTE generates poor-quality synthetic samples.	Target 1:10 ratio (sampling_strategy=0.1). Pair with scale_pos_weight for residual imbalance.
Threshold at 0.5	High	Default threshold is severely biased toward majority class at 235:1 ratio.	Sweep predict_proba thresholds, pick peak-F1 threshold. Report precision@recall=0.80.
Distribution shift	Medium	Public training data and private desktop data may have different typing distributions.	Run KS-test per feature before merge. Apply per-user z-score normalisation if p < 0.05.
Overfitting minority	Low	Heavy class weighting can cause model to memorise the 223 real stress samples.	Monitor train vs val minority F1 gap. Use early_stopping_rounds in XGBoost.
